In this case study, we run **[Prisma](https://prisma.altenwald.com/)** over **[Ecto](https://github.com/elixir-ecto/ecto)**, Elixir's flagship data-mapping and language-integrated query toolkit. With **58 `.ex` source files** compiling into **104 BEAM modules** full of macros, protocols, structs, recursive `Macro.t()` ASTs, and complex `@spec` contracts, Ecto is a demanding real-world stress test for Elixir static analysis.

Using Prisma's hybrid analyzer (`v0.2.4`) on Elixir `1.20.4` / OTP `29`, the entire Ecto codebase is checked in **0.65 seconds** (`0.631s–0.689s`). Prisma surfaced **3 real `@spec` inconsistencies** and **7 unused private-function parameters** (`oxbow_code`) that Elixir 1.20's compiler left unreported. All fixes and a portable **`ecto_3.15.0-dev.pplt`** (`173 KB`) have been submitted upstream in **[elixir-ecto/ecto#4817](https://github.com/elixir-ecto/ecto/pull/4817)**.

## 2. Why Elixir 1.20.4 Missed These Findings

Compiling Ecto with **Elixir 1.20.4** produces **0 type warnings** across `lib/` (only 3 intentional error-case warnings in `test/`). That is expected given Elixir's current gradual set-theoretic type system roadmap:

1. **No `@spec` vs. body verification yet:** Elixir 1.20 infers types from patterns and guards inside a function, but does not cross-check traditional `@spec` attributes against the function body or callers.
2. **No structural dead-parameter analysis (`oxbow_code`):** Unused parameters in private functions (`defp`) are not flagged when prefixed with `_`.

Prisma reads Elixir's `debug_info` directly from `.beam` files, checks `@spec` contracts in **hybrid mode** (strict gradual subtyping where specs exist, success typing where they do not), and runs structural `oxbow_code` reachability analysis on private functions.

## 3. Real Bugs & Cleanups Found in Ecto

### A. `@spec` Mismatches (3)

1. **`Ecto.Repo.Assoc.query/4` (`lib/ecto/repo/assoc.ex:10`)**
   - **Declared:** `@spec query([list], list, tuple, (list -> list)) :: [Ecto.Schema.t]`
   - **Actual:** Every clause returns `[list]` (`[]`, `Enum.map(rows, fun)` where `fun :: (list -> list)`, and `[load_assocs(item, refls) | sub_structs]`), and `Ecto.Repo.Queryable.execute/4` pipes the result straight into `Ecto.Repo.Preloader.query/7`, whose `@spec` expects `[list]`.
   - **Fix:** Updated the return spec to `:: [list]`.

2. **`Ecto.Query.Builder.From.build/5` (`lib/ecto/query/builder/from.ex:80`)**
   - **Declared:** `@spec build(..., atom, ...)` for the `as` parameter.
   - **Actual:** Immediately matches `{:^, _, [as]}` for runtime-interpolated aliases (`from(p in Post, as: ^name)`), which is a 3-tuple AST rather than an `atom`.
   - **Fix:** Widened `as` in `@spec` to `atom | Macro.t()`.

3. **`Ecto.Query.Builder.Join.build/10` (`lib/ecto/query/builder/join.ex:155`)**
   - **Declared & Actual:** Same `@spec` narrowing (`atom` vs. `{:^, _, [as]}`).
   - **Fix:** Widened `as` in `@spec` to `atom | Macro.t()`.

### B. Unused Private Parameters (`oxbow_code`, 7)

All 7 findings are in **private (`defp`)** functions, so removing them preserves 100% of Ecto's public API and backwards compatibility:

- **`Ecto.Multi.apply_operation/4` -> `/3` (`lib/ecto/multi.ex:917`):** `_apply_args` was ignored across all 7 clauses (leftover from an earlier refactor; `_wrap` in `apply_operation/5` was also marked unused).
- **`Ecto.Query.Builder.Windows.build_runtime_window/2` -> `/1` (`lib/ecto/query/builder/windows.ex:158`):** `_env` was unused.
- **`Ecto.Changeset.put_relation/5` -> `/4` (`lib/ecto/changeset.ex:2223`):** `_opts` was unused (public `put_assoc/4` and `put_embed/4` signatures remain unchanged).
- **`Ecto.Repo.Preloader.maybe_pmap/3` -> `/2` (`lib/ecto/repo/preloader.ex:152`):** `_repo_name` was unused.
- **`Ecto.Repo.Schema` (`lib/ecto/repo/schema.ex:36, 476, 604`):** `_name` was unused in private `do_insert_all/7` -> `/6`, `do_insert/4` -> `/3`, and `do_update/4` -> `/3` (public `insert_all/5`, `insert/4`, and `update/4` remain unchanged).

## 4. What Ecto Taught Us About Prisma (`v0.2.4`)

Running Prisma against Ecto's heavy metaprogramming also exposed 6 real edge cases in Prisma itself, all fixed and covered by new tests in `v0.2.4`:

1. **Recursive types in tuple/list patterns:** `extract_tuple_elems/2`, `extract_list_elem/1`, and `list_tail_type/1` now treat `unresolved/1` types (such as `{recursive_ref, ...}` in `Ecto.Type.t()`) as `any` instead of `none`, fixing false `dead_code` in `Ecto.Type.dump/3` and `load/3` for `{:array, {:parameterized, _}}`.
2. **Heterogeneous cons patterns `[H | T]`:** `bind_pattern({cons, _, H, T}, ...)` now joins `HT` with `extract_list_elem(TT)` instead of assuming the whole list has `H`'s type (e.g. `[Access, :get]` in `Ecto.Query.Builder`).
3. **Elixir multi-`when` guards:** `when G1 when G2` in Elixir `elixir_v1` AST is a disjunction (`[[G1], [G2]]`), not a conjunction (`[[G1, G2]]`), eliminating false `dead_code` in `Ecto.Query.Builder.escape/5`.
4. **Open map updates (`%{m | k: v}`):** `update_map_type/2` on `any_map` or unresolved bases now preserves openness (`any_map`) rather than collapsing into a closed map with only the updated keys (`Ecto.Query.Planner.plan_subquery/6`).
5. **Elixir macro hygiene & intrinsics:** `&&`/`||` expansions (`x@...@Elixir.Kernel`) are recognized as macro-generated clauses in `infer_case`, and `Enum.__in__/2` (`-> boolean()`) and `IO.warn/1,2` (`-> :ok`) are modeled directly.
6. **Raise-only stub functions:** `prisma_oxbow` now exempts private stub helpers where every clause unconditionally raises/errors (such as `Ecto.Query.API.doc!/1` and `Ecto.Query.WindowAPI.doc!/1`).
